title: Connect your apps
description: Use Woolly from Claude Code, Claude Desktop, Cursor and any other MCP app.
---

Woolly speaks MCP, the Model Context Protocol. Any app that supports MCP can use it as its memory. For Ollama and apps that don't support MCP, use the [proxy](/docs/proxy). To learn what happens behind the scenes, see [How MCP works](/docs/mcp).

## One command

```sh
woolly connect
```

Woolly finds the AI apps on your computer and adds itself to each one:

```txt
Connecting Woolly (/opt/homebrew/bin/woolly)

  ✓ Claude Code     connected
  ✓   at startup    loads your profile when a session starts
  ✓ Claude Desktop  connected
  ✓ Cursor          connected
  - Windsurf        not found
  ✓ VS Code         connected

Restart Claude Desktop to load the change.
```

It works with Claude Code, Claude Desktop, Cursor, VS Code, Windsurf, Codex, Gemini CLI, LM Studio, opencode and AnythingLLM. It only adds a `woolly` entry and keeps the rest of each config as it was. Before it changes a file, it saves a copy next to it ending in `.woolly-backup`.

| Command | What it does |
| --- | --- |
| `woolly connect` | Connect every app it finds |
| `woolly connect cursor vscode` | Connect only these apps |
| `woolly connect --dry-run` | Show what would change without changing anything |
| `woolly connect cursor --agent support-bot` | Give the app only one agent's memories. `--user <id>` does the same for one user |
| `woolly disconnect` | Remove Woolly from the apps again |

The app names are `claude-code`, `claude-desktop`, `cursor`, `vscode`, `windsurf`, `codex`, `gemini`, `lmstudio`, `opencode`, `anythingllm`.

Claude Code and Codex are set up through their own `claude mcp add` and `codex mcp add` commands. The others are set up by editing their config files.

With `--user` or `--agent`, the app runs `woolly mcp --user <id>` or `woolly mcp --agent <name>`, so it only reads and writes that user's or agent's memories. See [An agent's own memory](/docs/mcp#an-agents-own-memory). Claude Code's startup hooks are skipped for a scoped connection, because they load your own memory. A scoped connect removes those hooks if an earlier `woolly connect` added them. You have to name the apps to scope, so your other apps keep your own memory. Claude Code and Codex don't show Woolly's saved arguments, so to take a scope off one of them, run `woolly disconnect claude-code` and then `woolly connect claude-code`.

## Claude Code plugin

If you use Claude Code, you can add Woolly as a plugin instead. The plugin sets up the same MCP server and the same hooks as `woolly connect`, and adds a `woolly-check` skill that checks your CLAUDE.md and other memory files against the code. You still need the `woolly` command installed first, see [Quickstart](/docs/quickstart).

```sh
claude plugin marketplace add rjcuff/woolly
claude plugin install woolly@woolly
```

Or inside Claude Code, run `/plugin marketplace add rjcuff/woolly` and pick Woolly from `/plugin`.

Use the plugin or `woolly connect claude-code`, not both, or every hook runs twice. `woolly connect` warns you if it finds the plugin. To switch from `woolly connect` to the plugin, run `woolly disconnect claude-code` first.

## Memory that loads by itself

In most apps, the AI has to decide to call Woolly before it knows anything about you. For Claude Code, `woolly connect` also adds a startup hook, so every session starts with your profile and the notes about the project you're in. You don't have to ask.

The hook runs `woolly context`. It prints your profile and the memories for the current project, which is the name of the git repo or folder. Other projects' notes are left out. See [Projects](/docs/projects). It stays under Claude Code's 10,000 character limit for startup context. To see exactly what Claude Code gets, run it yourself:

```sh
woolly context
```

The hook is saved in `~/.claude/settings.json`, and `woolly disconnect` removes it. If you'd rather not have it, delete the `SessionStart` entry that runs `woolly context`.

If a config file has comments, Woolly won't rewrite it. It prints the lines to paste in yourself instead.

## Pick up where you left off

When Claude Code compacts a long conversation, or a session ends (including `/clear`), Woolly saves a short handoff note for the project, with what you were working on, what got done, what was decided and what's next. The next session starts with it, in Claude Code or any other connected app.

A quick note is saved right away. If Ollama is running with a chat model, Woolly then writes a better summary in the background. Only what you and the assistant wrote is read, never tool output.

```sh
woolly handoff          # show where you left off in this project
woolly handoff --clear  # remove it
```

Other MCP apps can save a handoff too, with the `handoff` tool.

## Set it up by hand

Prefer to edit the configs yourself, or using another MCP app? Here's what `woolly connect` adds.

### Claude Code

```sh
claude mcp add --scope user woolly -- woolly mcp
```

To load your profile at startup, add this to `~/.claude/settings.json`:

```json title="~/.claude/settings.json"
{
  "hooks": {
    "SessionStart": [
      {
        "matcher": "startup|clear|compact",
        "hooks": [{ "type": "command", "command": "woolly context --app claude-code", "timeout": 10 }]
      }
    ]
  }
}
```

### Claude Desktop

The easiest way is to download [woolly.mcpb](https://github.com/rjcuff/woolly/releases/latest/download/woolly.mcpb) and double-click it. Claude Desktop installs Woolly as an extension, with nothing else to set up. It works on macOS, Windows and Linux.

Or open **Settings → Developer → Edit Config** and add Woolly:

```json title="claude_desktop_config.json"
{
  "mcpServers": {
    "woolly": { "command": "woolly", "args": ["mcp"] }
  }
}
```

Restart Claude Desktop.

### Cursor

With Woolly installed, click to add it to Cursor or LM Studio:

<InstallButtons />

Apps opened from the Dock or Start menu may not find `woolly` this way. If so, run `woolly connect cursor` or `woolly connect lmstudio` instead, which writes the full path.

Or add the same block to `~/.cursor/mcp.json`:

```json title="~/.cursor/mcp.json"
{
  "mcpServers": {
    "woolly": { "command": "woolly", "args": ["mcp"] }
  }
}
```

### VS Code

VS Code uses `servers` instead of `mcpServers`. Run **MCP: Open User Configuration** and add:

```json title="mcp.json"
{
  "servers": {
    "woolly": { "type": "stdio", "command": "woolly", "args": ["mcp"] }
  }
}
```

### AnythingLLM

`woolly connect anythingllm` adds Woolly to AnythingLLM Desktop's `plugins/anythingllm_mcp_servers.json`. If AnythingLLM doesn't show up as found, open its **Agent Skills** page once so it creates that folder, then run the command again. Press **Refresh** on the Agent Skills page to load Woolly. No restart is needed.

### Jan

In Jan, open **Settings → MCP Servers**, click **+**, and enter:

- Server Name: `woolly`
- Command: `woolly`
- Arguments: `mcp`

Turn on the server. If it doesn't connect, restart Jan.

### Msty Studio

In Msty Studio, open **Toolbox**, choose **Add New Tool**, pick **STDIO / JSON**, and paste:

```json
{ "command": "woolly", "args": ["mcp"] }
```

<Callout title="Command not found?">
  If the app can't find `woolly`, use the full path. Run `which woolly` to get it.
</Callout>

## What your AI can do

| Tool | What it does |
| --- | --- |
| `remember` | Save a fact |
| `recall` | Search your memories |
| `get_profile` | Get a summary of what Woolly knows about you |
| `list_memories` | List current memories |
| `forget` | Move a memory to the trash, only when you ask |
| `resolve_conflict` | Keep one version of a disputed fact |

Woolly also tells the AI to recall context at the start of a task, and to mark facts it guessed as guesses. See [How MCP works](/docs/mcp) for an example.
