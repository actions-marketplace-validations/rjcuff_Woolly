title: JavaScript
description: Add Woolly memory to JavaScript and TypeScript apps, including the Vercel AI SDK.
---

```sh
npm install woolly-ai
```

Woolly needs to be running. [Download the Mac or Windows app](https://usewoolly.com/download) or run `woolly serve`.

## Save and recall

```ts
import { Woolly } from 'woolly-ai';

const w = new Woolly({ app: 'My app' });

await w.remember('Moved to Denver in October', { key: 'user.location' });
for (const m of await w.recall('where do I live?')) console.log(m.content);
```

Give a `key` for facts that can change. A newer memory with the same key replaces the older one. `app` is the name your memories are saved under and how your app shows up in `woolly log`.

A project fact can also say what kind of fact it is and which code it's about, so `woolly check` can flag it when that code changes. See [Stale facts](/docs/stale-facts).

```ts
await w.remember('The IMU chip select is GPIO 5', { project: 'drone', type: 'hardware', sources: ['main/pins.h#IMU_CS'] });
```

## Add memory to a prompt

```ts
const system = `You are a helpful assistant.\n\n${await w.context(userMessage)}`;
```

`context` returns the relevant memories as a short note that tells the model they're information, not instructions, or an empty string when nothing is relevant.

## Vercel AI SDK

Wrap any model and every call gets the user's relevant memories as a system message:

```ts
import { generateText, wrapLanguageModel } from 'ai';
import { woollyMemory } from 'woolly-ai/ai-sdk';

const model = wrapLanguageModel({ model: yourModel, middleware: woollyMemory() });
const { text } = await generateText({ model, prompt: 'Any snack ideas?' });
```

It takes `limit` (memories per call, default 6), `project`, and any `new Woolly()` option. If Woolly isn't running, calls go through unchanged.

## Memory for the agents you build

The same API as mem0, on your own machine. `add` turns a conversation into memories for one user, and a local model decides whether each fact is new, updates an older one, or is no longer true. `search` finds them before your agent answers.

```ts
await w.add(
  [
    { role: 'user', content: 'I just moved to Austin' },
    { role: 'assistant', content: 'Nice!' },
  ],
  { userId: 'alice' },
);
// [{ memory: 'Lives in Austin', event: 'UPDATE', previous_memory: 'Lives in Denver', ... }]

const memories = await w.search('where does she live?', { userId: 'alice' });
```

Scope with `userId`, `agentId`, `runId` or `project`. Also `getAll`, `history` (every version of a memory), `deleteAll` and `dream`, which merges duplicates and settles facts that changed. Pass `infer: false` to `add` to save messages as they are, without a model. See [Memory API for agents](/docs/memory-api).

Give memories a type and ask for just that kind, link related memories, and tell Woolly what helped:

```ts
await w.add('To reset a password, send the link from the admin page', { userId: 'alice', infer: false, memoryType: 'procedure' });
const steps = await w.search('reset a password', { userId: 'alice', type: ['procedure'] });

await w.link(steps[0].id, otherId, { userId: 'alice' }); // recall one, get both
await w.feedback(steps[0].id, true, { userId: 'alice' }); // ranks it a little higher next time

for (const c of await w.scopedConflicts({ userId: 'alice' })) {
  await w.resolveScoped(c.memory.id, { userId: 'alice' }); // throws if it would replace something more trusted
}
```

`recall` takes `type` too.

## Learn from a conversation

With Ollama running, a local model picks out the facts worth keeping. See [Smart memory](/docs/learn).

```ts
const steps = await w.learn([
  { role: 'user', content: 'I just moved to Denver. Keep answers short.' },
]);
```

## Everything else

`list`, `get`, `update`, `forget`, `restore`, `trash`, `conflicts`, `resolve` and `profile`. `resolve` throws if it would let a less trusted memory replace one you saved; settle those on the review page. Pass `project` to keep notes about one codebase separate, see [Projects](/docs/projects).

Errors are `WoollyError`, with `status` set to the HTTP status. When nothing answers at Woolly's address you get `WoollyNotRunning`.

`new Woolly()` uses `WOOLLY_HOST` and `WOOLLY_HOME` like the rest of Woolly. Requires Node 18 or newer.
