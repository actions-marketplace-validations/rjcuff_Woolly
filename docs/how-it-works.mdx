## Memories are files

Each memory is one Markdown file in `~/.woolly/memories`, with a short header on top:

```md title="~/.woolly/memories/20261110-150029-4fe20388.md"
---
id: 20261110-150029-4fe20388
key: user.location
source: user
status: active
created_at: 2026-11-10T15:00:29Z
---

Moved to Denver in October
```

You can open, edit or delete these files yourself. Woolly picks up changes right away.

## Facts that point at the code

A project fact can say what kind of fact it is and which code it's about, so Woolly can tell when the code changes underneath it:

```md title="~/.woolly/memories/20261117-153000-1a2b3c4d.md"
---
id: 20261117-153000-1a2b3c4d
source: agent
status: active
created_at: 2026-11-17T15:30:00Z
project: drone
commit: 3f2c1ab
type: hardware
sources: main/pins.h:12-18@77aa01b3, main/imu.c#imu_init@9b1e2f04
confidence: 0.8
---

The IMU's chip select is GPIO 5
```

| Field | Meaning |
| --- | --- |
| `type` | `decision`, `convention`, `gotcha`, `bug` or `hardware` |
| `sources` | The code the fact is about: a file (`main/imu.c`), a function, type, macro or constant in it (`main/imu.c#imu_init`) or a range of lines (`main/pins.h:12-18`). The part after `@` is a fingerprint of that code when the fact was saved. |
| `commit` | The commit the fact was saved at |
| `run_id` | The session it came from, when an app sets one |
| `confidence` | How sure Woolly is, from 0 to 1. Left out, it's 1 for things you said and lower for things an AI inferred. |
| `created_at`, `invalid_at` | When the fact became true and when it stopped being true (valid from and valid to) |

When the code a fact points at is removed or changes in a way that contradicts it, Woolly marks the fact `stale` with a reason and the commit that did it, keeps it out of search and session briefs, and asks you to review it. Nothing is deleted.

When each memory was last used is kept in `~/.woolly/usage.json`, not in the memory files, so searching never rewrites them.

Files from older versions load as they are. They just have no type or sources until you add them.

## Keeping facts current

Most memory tools keep everything forever, so your AI keeps bringing up things that stopped being true. Woolly handles change on purpose.

| What happens | What Woolly does |
| --- | --- |
| You save the same thing twice | Keeps one copy and refreshes its date |
| A new fact has the same `key` | Marks the old one superseded and hides it from search |
| An AI contradicts something you said | Saves it as a conflict and keeps your version |
| The code a fact points at changes | Marks it stale and asks you to review it |

## Who said it

Every memory records where it came from. When two facts disagree, the more trusted source wins.

1. **user** means you said it
2. **import** means it came from another app's export
3. **agent** means an AI inferred it

Review disagreements with `woolly conflicts`, and keep the right one with `woolly resolve <id>`.

## Search

Woolly ranks memories by matching words, with a small built-in list of related words so a question like "where do I live" finds "moved to Denver". If [Ollama](/docs/ollama) is running, Woolly also matches by meaning.

## Secrets and planted instructions

Woolly refuses to save anything that looks like a password, API key, private key, card number or Social Security number. This applies to the command line, AI apps, the API and imports. If you really need to save one, use `woolly remember --allow-secret`.

Woolly also refuses text from an AI or an import that reads like instructions to an AI, like "ignore your instructions". See [Security](/docs/security).
