You switch between Claude Code, Cursor and Codex on the same repo, and each one starts from zero. You explain the pin map again, the config value you settled on, the gotcha that cost you a day. Tools that do remember have a worse problem. They keep repeating facts the code stopped backing up weeks ago.

**Woolly is project memory your coding agents can trust.** It's local, every agent shares it, and every fact cites the code it came from. When that code changes, Woolly marks the fact [stale](/docs/stale-facts) instead of letting your agent follow it.

## Why Woolly

<Cards>
  <Card title="It knows when it's wrong" description="Rename a function, delete a file or change a value, and the facts that relied on it are flagged with the commit that broke them." />
  <Card title="Every fact cites its source" description="A file, function or line range, the commit, and the session it came from." />
  <Card title="One memory for every agent" description="Claude Code, Cursor and Codex read and update the same notes, and teammates get them through git." />
  <Card title="Files you can read" description="Every memory is a Markdown file. Edit it, search it, back it up, put it in git." />

## Also in Woolly

- **Personal memory.** Facts about you, like how you like to work, follow you across every AI app. See [How it works](/docs/how-it-works).
- **Memory for the agents you build.** An API shaped like mem0's, with [Python](/docs/python) and [JavaScript](/docs/javascript) packages. See [Memory API](/docs/memory-api).
- **Memory for Ollama.** [woolly proxy](/docs/proxy) adds memory to Ollama, OpenAI and Anthropic apps.

## Private by design

Woolly never sends your memories anywhere. There is no cloud, no telemetry and no sign-in. Everything stays in `~/.woolly` on your machine, and project memory stays in your repo.

<Callout title="Do I need Ollama?">
  No. Woolly works fully on its own, and stale detection never needs a model. If you run [Ollama](/docs/ollama), Woolly also uses it to search by meaning and to pick out decisions and gotchas when a session ends.
</Callout>
