---
title: Sync your devices
description: Keep your memories in step between your laptop, desktop and a Raspberry Pi. No cloud, no account.
---

Woolly can keep your memories the same on all your devices. They talk directly over your own network, and everything they send is encrypted. Away from home, sync through a folder you already sync instead, like Syncthing, Dropbox or a git repo. See [Sync through a folder](#sync-through-a-folder).

## Link two devices

On the first device:

```sh
woolly sync init
```

```txt
Sync is set up on this device.

On your other device, run:

  woolly sync join 192.168.1.20 Xb3k...
```

Run that command on the other device. It links the two and syncs right away. To add a third device, run the same join command there.

The first device needs to be running Woolly for the others to reach it. Run `woolly service install` so it always is.

## Keeping in step

`woolly serve` and the background service sync with your other devices every 5 minutes. To sync right now:

```sh
woolly sync
```

| Command | What it does |
| --- | --- |
| `woolly sync init` | Set up sync and print the join command |
| `woolly sync join <address> <code>` | Link this device to another |
| `woolly sync` | Sync now |
| `woolly sync status` | List linked devices and when they last synced |
| `woolly sync leave` | Stop syncing on this device. Your memories stay |

## How it works

- Each device lists its memories with the time each one last changed, and the newer copy wins.
- Forgetting a memory moves it to the trash on every device. Emptying the trash deletes it everywhere for good.
- Devices listen on port `11437`. Your computer may ask once whether to allow it.

## Is it safe?

The join code is a secret key that only your devices have. It's never sent over the network. Every message between devices is encrypted and signed with it, so another computer on your network can't read your memories or send fake ones. Old messages are refused, so a recorded one can't be replayed.

Keep the code private. Anyone with it, on your network, can read and change your memories. If it leaks, run `woolly sync leave` on every device and set sync up again.

## Sync through a folder

Devices on different networks can't reach each other directly. Point Woolly at a folder that some other tool already keeps in step between your computers, and Woolly syncs through it:

```sh
woolly sync folder ~/Sync
```

Woolly writes your memories into a `woolly-sync` folder inside it, encrypted with your join code, and prints the command for your other devices. To see the code again later, run `woolly sync status --show-code`.

```sh
woolly sync folder ~/Sync --code <code>
```

On each device, use the path where that same folder lives. Woolly checks the folder every 5 minutes while it runs (`woolly serve` or `woolly service install`), and when you run `woolly sync`.

Good tools for the folder:

- **Syncthing:** syncs a folder between your computers directly, with no account.
- **Dropbox, iCloud Drive, OneDrive or Google Drive:** any synced folder works. The provider sees only encrypted files.
- **A private git repo:** Woolly never runs git for you. Commit, push and pull the folder yourself, or with a scheduled job. Each memory is its own file, so two devices rarely change the same one. If git does report a conflict in a `.woolly` file, keep either version. The device that has the newer memory writes it back on its next sync.

Every file in the folder is encrypted and signed with the join code, and file names are scrambled, so whoever holds the folder can't read your memories or their IDs. A file that was changed or doesn't open with your code is skipped, and `woolly sync` says how many. Copies a sync tool makes when two devices change the same file, like `.sync-conflict-` files, are left alone. Keep the code private: anyone with it and the folder can read your memories.

`woolly sync folder <path> --remove` stops syncing through a folder and leaves its files alone. A device that only syncs through folders doesn't listen on the network.

Want sync away from home with nothing to set up? `woolly sync status` has a link to tell us.

## Raspberry Pi and other small devices

Woolly is one small program, so it runs on a Raspberry Pi. The install script picks the right build for 64-bit and 32-bit Raspberry Pi OS:

```sh
curl -fsSL https://usewoolly.com/install.sh | sh
```

A Pi that's always on makes a good home for Woolly. Link your other devices to it so they stay in step even when your laptop is closed.
