---
title: How MCP works
description: What happens when Claude, Cursor or another AI app uses Woolly.
---

MCP, the Model Context Protocol, is a standard way for AI apps to use outside tools. Woolly is one of those tools. Once you [connect an app](/docs/connect), the AI can save and look up memories on its own.

## What happens, step by step
### The app starts Woolly

When you open Claude Code, Claude Desktop or Cursor, the app runs `woolly mcp` in the background. You don't start anything yourself, and `woolly serve` doesn't need to be running.
### They introduce themselves

The app tells Woolly its name, and asks what it can do. Woolly answers with its list of tools and a short note telling the AI how to use them, like "recall context at the start of a task" and "never save secrets".
### The AI decides when to use a tool

While you chat, the AI reads the tool descriptions and calls one when it helps. Many apps ask your permission the first time a tool is used.
### Woolly does the work

Woolly reads or writes the memory files in `~/.woolly` and sends back a short text answer, which the AI uses in its reply. Recalled memories are labeled as notes about you, so the AI treats them as information, not instructions.
## An example

You tell Claude:

> I moved to Denver last month.

Claude calls the `remember` tool:

```json
{ "content": "Moved to Denver", "key": "user.location", "source": "user" }
```

Woolly saves it, marks your old location as replaced, and answers:

```txt
Remembered: Moved to Denver (key: user.location; source: user)
Replaced older memory: Lives in Austin
```

A week later, in Cursor, you ask for a weather script. Cursor calls `recall` with "user location", gets "Moved to Denver", and uses it.

## The tools

| Tool | When the AI uses it |
| --- | --- |
| `recall` | To look up anything relevant to what you're working on, in your memory and the project's. `max_chars` caps how much text comes back, and `type` keeps only some kinds, like `["procedure"]` |
| `get_profile` | Once at the start of a conversation, for a summary of you |
| `remember` | When you share a fact, preference or decision worth keeping. Its `scope` is `personal`, `project` or `auto`, so facts about the codebase go to [project memory](/docs/project-memory) and facts about you stay personal. Project facts can also have a `type` and `sources`, the code they're about, so Woolly can flag them when that code changes |
| `link_memories` | To tie two related memories together, like a decision and the bug behind it |
| `rate_memory` | When a recalled memory was clearly right or clearly wrong for the task, so it ranks higher or lower next time |
| `list_memories` | When you ask what Woolly knows. Lists 50 memories, newest first, unless you pass `limit` |
| `forget` | Only when you ask it to delete something. The memory goes to the trash, so you can restore it |
| `resolve_conflict` | Only when you confirm which version of a fact is right. It can't make a memory an AI saved win over one you saved; you settle those on the review page or with `woolly resolve` |
| `decide` | When you make a choice or turn down an approach, to save it with the reason and what was rejected. Its `sources` tie it to the code it's about |
| `why` | Before changing code it didn't write in this session, to read the decisions and gotchas behind it. See [Why is this code like this](/docs/why) |
| `check_memory_files` | Before trusting a note in CLAUDE.md, AGENTS.md or its own memory that names code, or when you ask if your agent files are up to date. See [Check your agent files](/docs/memory-files) |
| `handoff` | When you finish a piece of work, to save where you left off for the next session |

## Who said it

Every memory records where it came from. Woolly also refuses text from an AI that reads like instructions to an AI, so a malicious web page can't plant commands in your memory. See [Security](/docs/security).

 The AI marks a fact as `user` only when you said it directly, and as `agent` when it inferred it. Woolly can't check the AI's word, so a fact the AI says came from you is saved as `import` with the tag `user-stated`: above the AI's own guesses, below what you typed yourself. If an AI's version disagrees with something you saved, yours stays current and the AI's is saved as a conflict. Review those with `woolly conflicts` or on the [review page](/docs/review).

## An agent's own memory

To give an agent you build its own memory instead of yours, start the server with a user or agent:

```json
{ "command": "woolly", "args": ["mcp", "--agent", "support-bot", "--user", "alice"] }
```

It then saves to and searches only that user's or agent's memories, the same ones the [memory API](/docs/memory-api) reaches with `user_id` and `agent_id`, and never sees yours.

## Projects

When an app works in a git repo, Woolly tells it the project's name. The AI saves facts about the codebase to that project and facts about you to everyone, and searches leave other projects out. See [Projects](/docs/projects).

## Which app did what

Woolly records the name each app gives when it starts, like Claude Code or Cursor. Every memory notes the app that saved it, and `woolly log` lists what each app saved, read and deleted. The log stays on your computer.

## Sharing between apps

Each connected app runs its own copy of `woolly mcp`, but they all read and write the same files. Woolly notices changes right away, so a memory saved in Claude is there for Cursor a second later.

## Privacy

The app and Woolly talk directly on your computer, not over the internet. Woolly has no servers. What the AI app itself does with the answers it gets is covered by that app's privacy policy.

## Troubleshooting

### The AI never uses Woolly

Check that the app lists Woolly as connected. In Claude Code, run `claude mcp list`. In Claude Desktop and Cursor, look in the app's MCP or tools settings. Restart the app after changing its config.

### The app says it can't find woolly

Apps don't always see the same `PATH` as your terminal. Use the full path in the config. Run `which woolly` to get it.

### I want to see what the AI saved

Run `woolly log` to see what each app saved, read and deleted. Or open the [review page](/docs/review) with `woolly ui` and pick **Activity**.

### The AI saved something wrong

Edit or forget it on the review page, or run `woolly forget <id>`.
