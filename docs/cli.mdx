title: Commands
description: Everything the woolly command can do.
---

| Command | What it does |
| --- | --- |
| `woolly remember <text>` | Save a fact |
| `woolly recall <query>` | Search your memories |
| `woolly check` | Check this repo's facts, and the lines in CLAUDE.md, AGENTS.md, Cursor rules, Copilot instructions, Claude Code's memory, Codex memories and claude-mem, against the code. Flags what went stale, and exits with status 1 when something did. `--fix` rewrites renamed names and moved paths in agent files, `--no-memory-files` checks only facts, `--markdown` prints a pull request comment, `--json` prints everything with a `summary` of the counts and a `state` of `new` or `before` on each finding, `--status-json` prints only counts and file:line pointers with no text, `--status-file <path>` writes that next to another format, and `--base <commit>` compares against that commit, so findings from before it count as already stale. See [Check your agent files](/docs/memory-files), [Stale facts](/docs/stale-facts) and [Pull request checks](/docs/pull-requests) |
| `woolly welcome` | Show the mammoth and the three commands to start with, as the installer does |
| `woolly review` | Confirm, fix or retire stale facts, one at a time. `--list` only lists them, and `--confirm <id>` or `--retire <id>` settle one. `--old` lists AI guesses nothing has used in 90 days, and `--keep <id>` keeps one |
| `woolly why <file[:line\|#name]>` | The decisions, conventions and gotchas behind a file, a line or a function, and whether the code still backs each one up. See [Why is this code like this](/docs/why) |
| `woolly caught` | The stale facts Woolly kept away from your agents in this repo. `--badge` prints a README badge with the count |
| `woolly recap` | What Woolly did while you were away: what the last dream tidied and the lessons it learned. See [Dreaming](/docs/dreaming) |
| `woolly list` | Show current memories |
| `woolly show <id>` | Show one memory in full |
| `woolly forget <id>` | Move a memory to the trash |
| `woolly restore <id>` | Bring a memory back from the trash |
| `woolly trash` | List the trash, or delete it for good with `--empty` |
| `woolly import <chatgpt\|claude> <file>` | Import facts from your chat history |
| `woolly profile` | Summary of everything Woolly knows about you |
| `woolly ui` | Open the review page in your browser |
| `woolly conflicts` | Review facts that disagree |
| `woolly resolve <id>` | Keep this version as the current fact |
| `woolly learn [text]` | Pick out facts from text with a local model. See [Smart memory](/docs/learn) |
| `woolly sync` | Keep memories in step between your devices. See [Sync your devices](/docs/sync) |
| `woolly handoff` | Where you left off in this project. See [Pick up where you left off](/docs/connect#pick-up-where-you-left-off) |
| `woolly decide <choice>` | Save a decision, with `--why` and `--rejected "option: reason"`. `--source-ref` ties it to the code it's about, so `woolly why` finds it. See [Decisions](/docs/projects#decisions) |
| `woolly init` | Keep this repo's project memory in `.woolly/woolly.md`, shared with your team through git. `--export claude,agents` also keeps a section in CLAUDE.md and AGENTS.md. `--no-capture` stops saving decisions when a session ends. `--hooks` checks memory against the code after every commit, and `--no-hooks` stops that. `--stop` removes it. The first time, it brings in what CLAUDE.md, AGENTS.md and other agent files already say, unless you pass `--no-import`. See [Project memory](/docs/project-memory) |
| `woolly project` | Show this repo's project memory by heading. `woolly project edit` opens it in your editor |
| `woolly log` | What each app saved, read and deleted |
| `woolly context` | Print your profile and notes about the current project, for an app to read at startup. Facts that went stale are left out and named, and the last dream's recap shows once |
| `woolly connect [app...]` | Add Woolly to your AI apps. See [Connect your apps](/docs/connect) |
| `woolly disconnect [app...]` | Remove Woolly from your AI apps |
| `woolly service install` | Run Woolly in the background and start it at login |
| `woolly service status` | Show whether the background service is running |
| `woolly service uninstall` | Stop it and remove it from login |
| `woolly serve` | Run the local HTTP API and review page. Add `--proxy` to run the proxy too |
| `woolly mcp` | Run as an MCP server for AI apps |
| `woolly proxy` | Give memory to Ollama and OpenAI or Anthropic apps. See [Proxy](/docs/proxy) |
| `woolly update` | Update to the latest version. `--check` only checks |
| `woolly doctor` | Check your setup, and list any memory files Woolly couldn't read |
| `woolly version` | Print the version |

IDs can be shortened to any unique prefix, like `woolly show 20261110-1500`.

## remember

```sh
woolly remember "Moved to Denver in October" --key user.location --tags home
```

| Flag | Meaning |
| --- | --- |
| `--key` | Names the fact so a newer one can replace it |
| `--tags` | Comma-separated tags |
| `--project` | Only for this project, like a repo name. See [Projects](/docs/projects) |
| `--source` | `user` (default), `agent` or `import` |
| `--type` | For project facts: `decision`, `convention`, `gotcha`, `bug` or `hardware` |
| `--source-ref` | For project facts: the code it's about, like `main/imu.c#imu_init` or `main/pins.h:12-18`. Comma-separated. |
| `--allow-secret` | Save even if it looks like a password or API key |
| `--json` | Print the result as JSON |

## recall

```sh
woolly recall "where do I live" -n 3
```

| Flag | Meaning |
| --- | --- |
| `-n` | How many results, default 5 |
| `--all` | Include superseded and conflicting memories |
| `--project` | Search your memories plus this project's, and leave other projects out |
| `--json` | Print results as JSON |
| `--explain` | Show how each result was scored: keyword and meaning match, then freshness, confidence, use and status |

## import

```sh
woolly import chatgpt ~/Downloads/export.zip --dry-run
```

| Flag | Meaning |
| --- | --- |
| `--dry-run` | Show what would be imported without saving |

See [Import your history](/docs/import).

## profile

```sh
woolly profile
```

```md
# About me

## Facts

- Moved to Denver in October

## Preferences

- I prefer short answers
```

Add `--json` for JSON.

## forget, restore and trash

```sh
woolly forget 20261110-1500
woolly trash
woolly restore 20261110-1500
woolly trash --empty
```

Forgetting moves a memory to the trash. It's only gone for good after `woolly trash --empty`.

## list

```sh
woolly list --all
woolly list --project acme
```

## log

```sh
woolly log
```

```txt
Nov 11 09:12  Claude Code    loaded your profile at startup, plus 2 about this project
Nov 11 09:14  Cursor         searched for "database setup", got 3
Nov 11 09:15  Cursor         saved Uses Postgres 17 for the acme app
Nov 11 10:02  command line   deleted Lives in Austin
```

Shows the newest first. `--app cursor` shows one app, `-n 200` shows more, and `--json` prints JSON. The log is kept in `~/.woolly/activity.log` and never leaves your computer.

Every memory also records the app that saved it. `woolly show <id>` and the review page show it as "via Cursor".

## dream

```sh
woolly dream --dry-run
woolly dream --project acme
```

Folds repeats together, merges duplicates, settles facts that contradict each other, and with `--project` writes lessons from that project's past sessions. `--no-learn` skips lessons, `--user` keeps it to one `user_id`, and `--json` prints JSON. See [Dreaming](/docs/dreaming).

## context

```sh
woolly context
```

Prints your profile and the memories that mention the current project, framed as notes for an AI. `woolly connect` sets Claude Code to run it when a session starts. See [Memory that loads by itself](/docs/connect#memory-that-loads-by-itself).

## service

```sh
woolly service install
```

Runs `woolly serve --proxy` in the background and starts it when you log in. It needs no admin rights.

| System | How |
| --- | --- |
| macOS | A LaunchAgent at `~/Library/LaunchAgents/com.usewoolly.woolly.plist` |
| Linux | A systemd user service at `~/.config/systemd/user/woolly.service` |
| Windows | A startup entry for your account, with no console window |

Output goes to `~/.woolly/logs/woolly.log`. `woolly service status` shows whether the API and proxy are up, and `woolly doctor` includes it too.
